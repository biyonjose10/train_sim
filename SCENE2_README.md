# Scene 2 — Station Boarding

The train has stopped at the platform. The last signal is red for ten seconds. We spend nine of
them inside the station watching passengers board, then cut back to the train so the signal is on
screen when it goes green and the player takes over.

Scene file: `Assets/Scenes/Scene2_StationBoarding.unity`

## Timing

| t | What happens |
|---|---|
| 0.0 s | Signal red. Station shot A — wide, from under the west shelter |
| 3.5 s | Station shot B — close at the carriage side |
| 6.5 s | Station shot C — across the tracks, red signal in frame |
| **9.0 s** | Cut to the train camera, third person behind the train |
| **10.0 s** | Red off, green on. "PRESS SPACE TO GO" fades in, control handed over |
| after | Space toggles the train between going and stopping |

All four times are fields on the `Scene2Director` component, so they can be retimed without
touching code.

## How the scene is built

`Scene2_StationBoarding.unity` starts as a straight copy of
`Assets/pixel horror abandoned rural  train station/Scenes/environment with station.unity`, so the
station geometry, lighting, fog and skybox are identical to the existing station — nothing was
re-placed by hand.

Everything added on top lives under one root object, **`SCENE 2 SETUP`**, and is generated by
`Assets/Editor/Scene2Builder.cs`:

```
SCENE 2 SETUP
├── Track                   4 × Straight rail along x = 0
├── train                   Train_Type A + TrainSpaceDrive
├── StationStopWaypoint     marks where the train comes to rest
├── signal                  Cylinder + Cube + 3 lamp spheres
├── Cameras                 Cam_Station_A / B / C, Cam_Train
├── Passengers              8 × Hitogatas + PassengerWalker
├── Passenger Paths         Queue and Door point per passenger
├── Scene2Director          the sequence, plus the scene AudioListener
└── UI → Canvas             the PRESS SPACE label
```

Menu items under **Tools > Train Sim**:

- **Probe Scene 2** — prints the real mesh bounds of the train, rail and passenger prefabs and
  the platform surface height. Run this first if anything is floating or sunk.
- **Build Scene 2** — rebuilds everything under `SCENE 2 SETUP`. Safe to re-run: it deletes the
  old root first, so the station layout underneath is never touched.
- **Add Scenes To Build Settings** — puts `SampleScene` and `Scene2_StationBoarding` in the scene
  list, which they must be in for either to load at runtime.

The layout numbers are the `const` block at the top of `Scene2Builder.cs`. Adjust and re-run
rather than dragging objects, so the scene stays reproducible.

The free-roam `Player` from the station scene is switched off in scene 2 — this chapter is on
rails, and its camera and audio listener would otherwise fight the director.

## Hooking scene 1 up to it

Nothing in scene 1 was changed. To make the handover work:

1. Open `Assets/Scenes/SampleScene.unity`.
2. Add an empty GameObject where the train should stop and drag it into
   `TrainStationButtonStop.stationStopWaypoint` if it is not already set.
3. Add **`ArriveAtStationLoader`** to the `train` object and set:
   - `Station Stop Waypoint` → the same waypoint the train brakes towards
   - `Next Scene Name` → `Scene2_StationBoarding` (already the default)
   - `Load Delay` → how long to linger after stopping before the cut, default 0.5 s
4. Run **Tools > Train Sim > Add Scenes To Build Settings** once.

`ArriveAtStationLoader` watches the distance to the waypoint and the train's own speed rather than
using a trigger volume, so it needs no tags and cannot silently fail on the empty tag list.

### What scene 2 assumes about scene 1

| | Value |
|---|---|
| Train position when stopped | `x = -2.4`, `y = 0.55` (carried over from scene 1), `z = 6` |
| Train heading | +Z, `rotation = identity` |
| Signal transform | position `(-5.9773, 3.0711, 18.459)`, uniform scale `1.3712` — scene 1's signal, verbatim |
| Boarding platform | west, `x ≈ -6.9`, which is the train's **left** as it faces the signal |

If scene 1's stop position moves, change `TrainStopZ` in `Scene2Builder.cs` and re-run the build.

## Passengers

`Hitogatas.fbx` imports as a Humanoid rig with a full skeleton, but it ships with **no animation
clips**, and there is no `.anim` or `.controller` anywhere in the project. So `PassengerWalker.cs`
drives the walk itself: it looks up `thigh_stretch.l/r` and `arm_stretch.l/r` by name and swings
them with a sine wave, with a small bob on `spine_01.x`.

If the figures look like they are swinging the wrong way, flip `Swing Axis` on the component (it
defaults to `(1, 0, 0)`). If the bones cannot be found at all it logs a warning and the figures
walk without swinging rather than breaking.

Each passenger walks to a **Queue** point on the platform, then to a **Door** point at the
carriage side, then deactivates. The train mesh has no door meshes and no interior, so the
carriage body is what hides the moment they disappear — keep the door points tight against the
train or the trick shows.

## Known issues in scene 1 (flagged, not fixed)

Scene 1 was left untouched as agreed. These are all live in the committed version:

- **No scripts are attached to anything** in `SampleScene.unity`. `TrainStationButtonStop` and
  `Signal1Trigger` exist as files but are not on any GameObject, so the scene does nothing on play.
- **`Signal1Trigger` can never fire.** It calls `other.CompareTag("Train")`, but
  `ProjectSettings/TagManager.asset` has `tags: []` — the `Train` tag does not exist. Adding it
  (Project Settings > Tags and Layers) and tagging the train fixes it.
- **The Main Camera is still at Unity's default** `(0, 1, -10)` and is not attached to the train.
  `TrainFollowCamera` from this branch can be dropped on it to get the third-person view scene 2
  cuts back to.
- **The signal lamps all use the built-in default material.** `New Material.mat` (red) and
  `New Material 3.mat` (yellow) are in the project but unused, and there was no green at all —
  scene 2 adds `Assets/Materials/Signal Green.mat`.

## Other notes

- There are no audio assets in the project, so scene 2 is silent.
- The scene file carries the lighting data reference it inherited from the station scene. That is
  intentional — the bake is what makes it look identical. If Unity ever complains, re-bake or
  clear the lighting data asset on the scene.
- Scene 2 duplicates the station geometry rather than sharing it with the original scene. If the
  station layout changes, delete `Scene2_StationBoarding.unity` and re-run **Build Scene 2** to
  pick the change up.
